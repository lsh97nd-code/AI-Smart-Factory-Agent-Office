# AI Smart Factory Agent Office

AI Native Final Project | 최종 발표 script

## 1장. 프로젝트 소개

안녕하세요.

저희가 개발한 AI Smart Factory Agent Office는 제조 설비에 이상이 있는지 진단한 뒤, 기술 문서를 근거로 사람에게 진단 결과와 권고 조치 사항까지 알려줍니다. 즉, 기존에 사람이 했던 의사결정 중 여러 과정을 하나의 Workflow로 자동화했습니다.

## 2장. 문제 정의

기존의 방식은 제조 설비에 이상이 감지되면, 담당자는 이를 분석해서 점검합니다. 그리고 기술문서에서 근거를 찾아서 원인이 무엇인지 파악한 뒤 설비를 정비할지 판단합니다. 이 과정에서 담당자는 숙련도에 따라 서로 다른 진단을 내릴 수 있습니다. 저희는 자료 검색·근거 확인·점검 계획 정리 과정을 하나의 Workflow로 연결해 작업자의 판단을 지원합니다.

## 3장. 해결 방식

시스템을 설명하면 우선, ML이 Bearing의 정상·이상 상태를 판별한 뒤 처리 경로를 결정합니다.

정상일 경우, 기술문서 검색이나 후속 진단 등을 하지 않고 바로 정상 보고서를 생성합니다.

그러나 이상일 경우, 관련 기술문서를 검색해서 근거를 확보합니다. AI Agent는 근거가 충분한지 확인하고, 이상 판별 시 원인을 진단합니다.

그리고 점검 계획을 세우고 권고 조치 사항을 알려주며, 중요한 사항은 작업자에게 알립니다.

즉, AI Agent는 설비의 상태에 따라 필요한 작업만 선택해서 수행합니다.

## 4장. 왜 AI Agent인가

저희 시스템은 AI Agent의 핵심 요소인 목표, 계획, 판단, 도구 활용, 기억, 피드백 기능을 갖추고 있습니다.

LangGraph가 현재 상황에 따라 다음에 어떤 작업을 할지 결정하고, 머신러닝, 문서 검색, 데이터베이스 같은 기능을 필요한 순서대로 연결합니다.

또한 과거 진단 이력과 현재 진행 상태를 저장하기 때문에, 작업이 중단되더라도 처음부터 다시 시작하지 않고 멈춘 지점부터 이어서 진행할 수 있습니다.

중요한 조치가 필요한 경우에는 작업자 판단을 기다립니다. 작업자는 승인·수정 요청·거절 중 하나를 선택하고, 시스템은 선택 결과를 반영해 중단된 Checkpoint에서 작업을 다시 수행합니다.

진단은 검색된 기술문서를 근거로 이루어지며, 핵심 진단 과정은 외부 언어모델 API 없이도 작동합니다.

## 5장. 핵심 구현 기술

세 종류의 Bearing에서 확보한 240건의 저장된 측정 Data 중 사용자가 선택한 Data를 시스템에 활용했습니다. 저장된 측정 Data의 신호를 해당 시간축에 따라 화면에서 재생(Replay)하여 작업자가 설비 상태의 변화를 확인할 수 있습니다.

같은 측정 데이터를 ML이 분석해 정상인지 이상인지 판단하고, 그 결과에 따라 AI Agent가 다음 진단 과정을 진행합니다.

머신러닝에는 진동과 전류 데이터에서 추출한 36개의 특징값을 사용했습니다.

이상이 감지되면 RAG를 이용해 기술문서를 검색합니다. 기술문서 15개를 검색하기 쉬운 183개 문서 조각(Chunk)으로 나누고, 각 조각을 384개의 숫자 특징으로 바꿔 저장했습니다. Chroma가 현재 상황과 관련 있는 문서 내용을 찾아줍니다.

AI Agent는 이렇게 찾은 기술문서를 근거로 진단을 진행합니다.

전체 진단 과정은 LangGraph라는 자동화 도구를 이용해 25개의 처리 단계로 연결했습니다. 앞 단계의 결과에 따라 다음에 필요한 작업을 자동으로 선택해서 진행하고, 마지막에는 최종 보고서까지 작성합니다.

(세부적인 기술 내용은 질의응답에서 설명드리겠습니다.)

## 6장. 세 가지 실행 결과

세 가지 실행 결과를 통해 실제로 검증한 내용을 말씀드리겠습니다.

첫 번째 A는 정상 Bearing입니다.

Machine Learning(ML)이 상태를 정상으로 판정하면서 RAG와 후속 진단을 생략하고 바로 정상 보고서를 생성했습니다.

두 번째 B는 Dataset에서 손상(damaged)으로 분류된 Bearing이며, ML은 이를 이상(abnormal)으로 판정했습니다.

이상으로 판정되면 RAG가 관련 기술문서를 검색합니다. AI Agent가 근거가 충분한지 확인하고, 이상 판별 시 원인을 진단한 뒤 추가 점검이 필요한 항목에 대한 점검 계획을 수립하고 작업자에게 조치 방법을 제안해 판단을 지원합니다. 이후 최종 보고서를 생성했습니다.

세 번째 C는 같은 손상 데이터를 사용하되, 중요한 조치 전에 작업자가 직접 확인하도록 설정한 시나리오입니다.

실제 Bearing 데이터를 분석해 상태를 진단한 뒤, 작업자 확인이 필요한 단계에서 작업을 일시적으로 멈췄습니다.

이후 작업자가 승인하면 작업을 처음부터 다시 시작하지 않고, 중단된 Checkpoint에서 이어서 작업을 완료했습니다.

즉, 이 결과를 통해 AI Agent가 단순히 작업자에게 승인 요청을 보내는 것뿐만 아니라, 실제로 작업을 멈추고 작업자의 판단을 기다린 뒤, 승인되면 멈췄던 지점부터 다시 작업을 이어서 진행하는 과정까지 확인했습니다.

## 7장. Workflow 검증 결과

검증 대상은 Machine Learning Model 하나만이 아니라, 측정 Data가 입력된 순간부터 최종 보고서가 만들어질 때까지의 전체 Workflow입니다.

Backend에서는 162개의 Test를 모두 통과했고, 화면의 상태를 관리하는 Frontend Test와 TypeScript 검사, 배포용 Build도 모두 통과했습니다.

RAG의 기술문서 검색 성능도 확인했습니다. Test 결과, Hit@5는 91.3%로 필요한 근거가 상위 5개 검색 결과 안에 포함된 비율이며, MRR은 0.862로 필요한 근거가 검색 결과의 앞쪽에 나타나는 정도입니다. 두 지표 모두 1에 가까울수록 검색 결과가 더 적절합니다.

또한 정상으로 판단했을 때와 이상으로 판단했을 때 서로 다른 절차로 작업이 진행되는지도 확인했습니다.

중요한 조치가 필요한 경우에는 작업을 멈추고 작업자의 판단을 기다립니다. 작업자는 승인, 수정 요청, 거절 중 하나를 선택할 수 있습니다. AI Agent는 작업자의 선택을 Workflow에 반영한 뒤, 처음부터 다시 시작하지 않고 중단된 Checkpoint에서 후속 작업을 다시 수행합니다.

이와 함께 과거에 수행한 진단 과정과 작성된 최종 보고서를 다시 확인할 수 있는지, 그리고 진단에 사용한 기술문서의 출처를 추적할 수 있는지도 검증했습니다.

마지막으로 Backend에서 발생한 AgentEvent를 SSE(Server-Sent Events, 서버 전송 이벤트)로 받아 검색·진단·승인 대기·완료 등 Workflow 상태를 화면에 표시합니다.

## 8장. AI Agent의 판단 근거와 사람의 최종 결정

작업자는 AI Agent의 권고 사항을 전달받았을 때, 이 결과를 신뢰할 수 있는지 의문을 가질 수 있습니다.

저희 System은 검색된 기술자료에 문서명, Page, 해당 Section, 문서 조각과 검색 점수를 함께 연결해 두었습니다.

그래서 작업자는 AI Agent가 어떤 기술자료를 근거로 판단했는지 직접 확인할 수 있습니다.

여기서 검색 점수는 현재 설비 상황과 검색된 기술문서의 내용이 얼마나 비슷한지를 나타내는 상대적인 점수입니다. 실제 고장 원인이 맞을 확률을 의미하는 것은 아닙니다.

또한 중요한 조치가 필요한 경우에는 AI가 임의로 작업을 진행하지 않고, 작업자가 승인, 수정 요청 또는 거절을 선택하도록 했습니다.

AI는 설비를 직접 제어하거나 정비를 대신하는 것이 아니라, 작업자가 판단할 수 있도록 근거와 정보를 제공해 의사결정을 지원합니다.

## 9장. AI Smart Factory Agent Office의 차별점과 활용 가치

저희 프로젝트의 차별점은 제조설비 진단에 필요한 여러 업무를 하나의 Workflow로 연결해 자동화한 것입니다.

저장된 측정 Data의 입력부터 Machine Learning, RAG, 작업자 확인, 이력 관리, 사용자 화면까지 하나의 시스템으로 구현했습니다.

이를 통해 작업자는 Bearing의 상태와 진단 근거를 확인하고, 다음 점검과 정비 판단에 활용할 수 있습니다.

## 10장. 현재 수준과 앞으로의 발전 방향

현재 저희 System은 저장된 Bearing 측정 Data를 활용한 MVP, 즉 최소 기능 제품입니다. 아직 실제 공장의 Sensor와 직접 연결해 시험한 단계는 아니며, 학습에 사용하지 않은 새로운 Bearing에서도 같은 성능을 낼 수 있는지는 추가 검증이 필요합니다.

기술문서 검색에도 한계가 있습니다. 현재는 문서에 사용된 단어의 특징을 숫자로 바꿔 비슷한 자료를 찾는 방식이기 때문에, 문장의 의미를 세밀하게 이해하는 데에는 한계가 있습니다. 앞으로는 단어가 비슷한 자료를 찾는 방식에 문장의 의미를 이해해서 검색하는 방식을 추가해 검색 성능을 높일 계획입니다.

또한 이 System이 Bearing에만 적용되는 구조인지도 확인해봤습니다. KAMP에서 제공하는 CNC 제조 Data 1,085건을 이용해 CNC Data를 받아들이는 별도의 입력 기능과, CNC 관련 기술문서를 검색하는 기능을 적용했습니다. 그 결과 Data 입력과 기술문서 검색에 대한 29개의 Test를 모두 통과했습니다.

다만 이 Test는 CNC Data를 System에 입력하고 관련 기술문서를 찾아 활용할 수 있는지를 확인한 것이며, CNC 설비의 이상을 판별하는 Machine Learning 성능까지 검증한 것은 아닙니다.

앞으로는 실제 Sensor와 제조 System을 연결하고, 새로운 Bearing과 다양한 운전 조건에서도 성능을 검증하면서 AI Agent를 고도화할 계획입니다. 이후에는 기업별 설비에 맞게 적용하고 운영 경험을 쌓아, 여러 제조 현장에서 활용할 수 있는 AI Agent Platform으로 발전시키고자 합니다.

저희의 목표는 AI가 작업자를 대신해 정비 여부를 결정하도록 하는 것이 아닙니다. AI가 작업자에게 설비의 이상과 그 근거를 알려주고, 다음에 무엇을 점검하고 조치해야 하는지 제안해서 작업자의 판단을 돕는 것이 목표입니다.

이상으로 발표를 마치겠습니다. 감사합니다.
